# Когорты и юнит-экономика интернет-магазина на SQL

**Отчёт:** https://wickedstacy085.github.io/ecommerce-sql · **Дашборд:** https://wickedstacy085.github.io/ecommerce-sql/dashboard.html

SQL-анализ 96 тыс. доставленных заказов бразильского маркетплейса [Olist](data/README.md) (2017–2018):
растёт ли бизнес за счёт постоянных клиентов и где теряет деньги и репутацию.

**Результаты.**
- Повторно покупают только 3,0% клиентов; за год повторные покупки добавляют к выручке с клиента ≈ 3% —
  привлечение должно окупаться первым заказом.
- 6,8% заказов опаздывают, и на них приходится 33% всех отзывов на 1–2 звезды; в RJ и BA опаздывает
  12% заказов против 4,5% в Сан-Паулу.
- Два сегмента с крупным чеком — 30% клиентов и 56% выручки; «ушедшие с крупным чеком» — кандидат на win-back-тест.

## Что внутри

| Папка | Содержимое |
|---|---|
| `sql/` | запросы DuckDB по слоям: `01_base` (заказ = строка, `customer_unique_id`), `02_cohorts`, `03_ltv`, `04_rfm`, `05_unit_economics`, `06_delivery`, `07_mart` |
| `tests/` | 22 проверки: число строк = оригиналу, выручка сходится, клиент в одной когорте и одном сегменте, LTV не убывает |
| `powerbi/` | витрина «звезда» (`fact_orders`, `dim_customers`), меры DAX, макет отчёта |
| `index.qmd`, `dashboard.qmd` | отчёт и интерактивный дашборд (Quarto + Plotly) |

SQL-приёмы: CTE, оконные функции (`row_number`, `ntile`, накопленные суммы), `qualify`, `generate_series`
для сетки когорт с нулевыми месяцами, `filter` в агрегатах.

## Как воспроизвести

```bash
pip install -r requirements.txt
pytest                         # проверки SQL-слоя
python scripts/export_mart.py  # витрина для Power BI
quarto render                  # отчёт и дашборд
```
