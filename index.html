Когорты и юнит-экономика интернет-магазина на SQL

SQL-анализ 96 тыс. заказов маркетплейса Olist: когорты, retention, LTV, RFM-сегменты, юнит-экономика и влияние доставки на отзывы. Интерактивный дашборд и витрина для Power BI.
Автор

Анастасия Смирнова

Дата публикации

22 ноября 2026 г.

Вопрос. Маркетплейс растёт: за 20 месяцев 96 211 доставленных заказов на R$ 15,4 млн. Растёт ли он за счёт постоянных клиентов — и где теряет деньги и репутацию?

Ответ. Нет: повторно покупают только 3,0% клиентов, и за год повторные покупки добавляют к выручке с клиента всего 3,0%. LTV ≈ первый заказ — значит, привлечение окупается только с первой покупки. Главная управляемая проблема — доставка: 6,8% заказов опаздывают, и на них приходится 33% всех негативных отзывов.

Данные

Olist — реальные обезличенные заказы бразильского маркетплейса, 8 связанных таблиц (лицензия CC BY-NC-SA 4.0). В анализе — доставленные заказы с января 2017 по август 2018: 96 211 заказов, 93 104 клиентов. Выручка заказа — товары плюс доставка.

Весь анализ — SQL-запросы в DuckDB (папка sql/), Python только выполняет их и рисует графики. Каждый запрос проверен тестами: число строк совпадает с оригиналом, выручка в отчётах сходится с позициями заказов, каждый клиент попадает ровно в одну когорту и один сегмент.

Ловушка в данных. customer_id в Olist новый у каждого заказа, поэтому по нему повторных покупок нет вообще. Человека идентифицирует customer_unique_id — с него начинается базовый слой:

-- Базовый слой: один доставленный заказ = одна строка.
-- Клиент — customer_unique_id: customer_id в Olist новый у каждого заказа,
-- и по нему повторных покупок не видно вообще.
create or replace view orders as
with items as (
    select order_id,
           sum(price + freight_value) as revenue,
           sum(freight_value)         as freight,
           count(*)                   as items
    from raw_order_items
    group by order_id
)
select o.order_id,
       c.customer_unique_id,
       c.customer_state                    as state,
       o.order_purchase_timestamp          as purchased_at,
       o.order_delivered_customer_date     as delivered_at,
       o.order_estimated_delivery_date     as estimated_at,
       i.revenue, i.freight, i.items
from raw_orders o
join raw_customers c using (customer_id)
join items i using (order_id)
where o.order_status = 'delivered'
  and o.order_purchase_timestamp >= (select period_start from params)
  and o.order_purchase_timestamp <  (select period_end   from params);

-- Один отзыв на заказ: самый поздний по дате ответа.
create or replace view order_reviews as
select order_id, review_score, review_creation_date
from raw_order_reviews
qualify row_number() over (partition by order_id
                           order by review_answer_timestamp desc, review_id) = 1;

Когорты: клиенты почти не возвращаются

В среднем через месяц после первой покупки возвращается 0,48% когорты, дальше — ещё меньше. Это не провал одного месяца, а свойство модели: на маркетплейс приходят за конкретной покупкой (крупнейшие категории по выручке — красота и здоровье, часы и подарки, товары для дома, спорт), а не за регулярными, как в продуктовом магазине.

-- Когорта = месяц первой покупки клиента; retention = доля когорты, купившая в месяце offset.
create or replace view customer_first as
select customer_unique_id,
       date_trunc('month', min(purchased_at)) as cohort_month
from orders
group by 1;

create or replace view customer_activity as
select distinct o.customer_unique_id, f.cohort_month,
       date_diff('month', f.cohort_month, date_trunc('month', o.purchased_at)) as "offset"
from orders o
join customer_first f using (customer_unique_id);

create or replace view cohorts as
with sizes as (
    select cohort_month, count(*) as cohort_size from customer_first group by 1
),
grid as (   -- все offset, которые когорта успела прожить, включая месяцы без покупок
    select s.cohort_month, s.cohort_size, g.o as "offset"
    from sizes s,
         generate_series(0, date_diff('month', s.cohort_month,
                                      (select date_trunc('month', max(purchased_at)) from orders))) g(o)
),
active as (
    select cohort_month, "offset", count(*) as customers
    from customer_activity group by 1, 2
)
select g.cohort_month, g."offset",
       coalesce(a.customers, 0)                   as customers,
       coalesce(a.customers, 0) / g.cohort_size   as retention,
       g.cohort_size
from grid g
left join active a using (cohort_month, "offset")
order by 1, 2;

LTV: выручка с клиента ≈ первый заказ

Линии почти горизонтальные: у 8 когорт, проживших год, выручка на клиента за 12 месяцев выросла в среднем на 3,0%. Для юнит-экономики это значит: стоимость привлечения клиента (CAC) должна окупаться маржой первого заказа — рассчитывать на возврат денег через повторные покупки нельзя.

Доставка: 7% заказов — треть негатива

Срок, который обещает Olist, консервативный: 79% заказов приезжает больше чем на неделю раньше. Но если заказ опаздывает, оценка падает резко: с 4,2 до 1,7 при опоздании на 8+ дней, и уже 79% таких отзывов — на 1–2 звезды. На повторные покупки опоздание почти не влияет (2,4% против 2,7%) — возвращаются мало в любом случае.

Опоздания сосредоточены в отдельных штатах:

-- Опоздание доставки → оценка в отзыве → вернулся ли клиент.
-- Срок, который Olist обещает, консервативный: большинство заказов приезжает на 1–2 недели раньше.
-- repeat_rate считается по первым заказам клиентов: доля тех, кто после него купил ещё раз.
create or replace view delivery_orders as
select o.*,
       date_diff('day', o.estimated_at::date, o.delivered_at::date)  as delay_days,
       case
           when date_diff('day', o.estimated_at::date, o.delivered_at::date) <= -7 then 'раньше на 7+ дней'
           when date_diff('day', o.estimated_at::date, o.delivered_at::date) <= 0  then 'в срок'
           when date_diff('day', o.estimated_at::date, o.delivered_at::date) <= 3  then '1–3 дня'
           when date_diff('day', o.estimated_at::date, o.delivered_at::date) <= 7  then '4–7 дней'
           else '8+ дней'
       end as bucket,
       r.review_score,
       row_number() over (partition by o.customer_unique_id order by o.purchased_at, o.order_id) = 1 as is_first,
       count(*)     over (partition by o.customer_unique_id) > 1                         as customer_repeated
from orders o
left join order_reviews r using (order_id)
where o.delivered_at is not null;

create or replace view delivery as
select bucket,
       count(*)                                               as orders,
       avg(delay_days)                                        as avg_delay_days,
       avg(review_score)                                      as avg_review,
       avg((review_score <= 2)::int)                          as share_1_2_stars,
       avg(customer_repeated::int) filter (where is_first)   as repeat_rate,
       count(*) filter (where is_first)                       as first_orders
from delivery_orders
group by 1
order by case bucket when 'раньше на 7+ дней' then 1 when 'в срок' then 2 when '1–3 дня' then 3
                     when '4–7 дней' then 4 else 5 end;

RFM: где деньги

R и M — квинтили, а F считается по числу заказов: при 97% разовых клиентов квинтили частоты бессмысленны — об этом стоит помнить, когда RFM применяют к маркетплейсам. Два сегмента с крупным чеком — это 30% клиентов и 56% выручки.

-- RFM. R и M — квинтили (5 — лучше). F по квинтилям не считается: 97% клиентов купили один раз,
-- поэтому F — по числу заказов: 1 заказ → 1, 2 → 3, 3+ → 5.
create or replace view rfm as
with c as (
    select customer_unique_id,
           date_diff('day', max(purchased_at),
                     (select max(purchased_at) from orders) + interval 1 day) as recency_days,
           count(*)     as frequency,
           sum(revenue) as monetary
    from orders
    group by 1
),
s as (
    select *,
           ntile(5) over (order by recency_days desc) as r,
           case when frequency = 1 then 1 when frequency = 2 then 3 else 5 end as f,
           ntile(5) over (order by monetary) as m
    from c
)
select *,
       case
           when f >= 3 and r >= 4             then 'Постоянные, недавние'
           when f >= 3                        then 'Постоянные, давно не покупали'
           when r >= 4 and m >= 4             then 'Новые, крупный чек'
           when r >= 4                        then 'Новые'
           when r <= 2 and m >= 4             then 'Ушедшие, крупный чек'
           when r <= 2                        then 'Ушедшие'
           else                                    'Спящие'
       end as segment
from s;

Рекомендации

  1. Считать окупаемость рекламы по первому заказу. Повторные покупки за год добавляют 3,0% выручки, поэтому целевой CAC — в пределах маржи первого заказа, а не «LTV».
  2. Чинить доставку в RJ и BA. Там опаздывает около 12% заказов против 4,5% в Сан-Паулу. Опоздания дают 33% негативных отзывов, а рейтинг продавца влияет на конверсию карточки — это гипотеза для следующего анализа, в данных о показах её не проверить.
  3. Проверить win-back на «Ушедших с крупным чеком». 13 741 клиентов со средней выручкой R$ 307 — единственный сегмент, где возврат даже нескольких процентов заметен в деньгах. Проверять A/B-тестом с контрольной группой, как в проекте про email-рассылку.

Ограничения

  • Данные одного маркетплейса за 2017–2018 годы; нет маржи, стоимости привлечения и данных о показах.
  • Последние когорты наблюдаются меньше месяцев — на графиках показаны только прожитые месяцы.
  • Связь «опоздание → оценка» — корреляция: опаздывают, возможно, определённые продавцы или категории.
